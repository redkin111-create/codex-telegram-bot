# Codex Remote Mini App — бесплатно через Tailscale Funnel

**Вся система работает на твоём домашнем Windows-ноутбуке.** Ни VPS, ни
собственный домен, ни Cloudflare, ни белый IP, ни открытые порты роутера не нужны.

```text
Телефон: Telegram Mini App (https://ноутбук.твой-tailnet.ts.net)
                      |
                HTTPS / Funnel (публичный адрес Tailscale)
                      |
               Tailscale на ноутбуке
                      |
                 127.0.0.1:3301
                      |
          Bot + Mini App + Codex app-server
```

Статический HTML доступен через публичный адрес, **но все запросы к Codex
требуют подлинный Telegram initData**: сервер проверяет HMAC, время выдачи
и числовой Telegram ID из существующего `ALLOWED_USERS`. Обращение к
сайту просто по адресу не предоставляет доступ к управлению.

## 1. Однократная установка Tailscale

1. Установи [Tailscale для Windows](https://tailscale.com/download/windows).
2. Войди в свой Tailscale-аккаунт на ноутбуке; убедись, что статус Connected.
3. В настройках tailnet включи MagicDNS, HTTPS certificates и Funnel.
   Первый запуск Funnel может запросить подтверждение администратора сети.
   [Официальная инструкция](https://tailscale.com/docs/features/tailscale-funnel).
4. Проверь из PowerShell:

```powershell
& "C:\Program Files\Tailscale\tailscale.exe" status
```

Если установлено в другом месте, укажи путь в переменной
`TMA_TAILSCALE_BIN`. Программа Tailscale должна запускаться вместе с
Windows (её собственная служба).

## 2. Включи Mini App в уже установленном боте

Обнови исходный форк на ноутбуке:

```powershell
git pull --ff-only origin main
npm ci
```

Добавь эти строки в существующий `.env` бота (обычно
`%USERPROFILE%\.codex\tg\.env`):

```dotenv
TMA_LOCAL=true
TMA_PORT=3301
TMA_TAILSCALE_AUTO=true
```

**Всё.** Не задавай `TMA_GATEWAY_URL`, `TMA_AGENT_TOKEN`,
`TMA_TUNNEL_CONFIG`, `TMA_CLOUDFLARED_BIN` или `TMA_PUBLIC_URL`.
Они не нужны для локальной TMA.

`TMA_TAILSCALE_AUTO=true` — явное разрешение автоматически настроить
публичную HTTPS-публикацию. При запуске бот:

1. Поднимает локальный шлюз и Codex на `127.0.0.1:3301`.
2. Проверяет, что Tailscale вошёл в аккаунт и разрешён Funnel.
3. Если нужная публикация ещё не настроена, вызывает
   `tailscale funnel --bg --yes --https=443 http://127.0.0.1:3301`.
4. Проверяет, что Funnel действительно ведёт на порт `3301`.
5. При ошибке пишет её в лог, **не останавливая Telegram-бота**.

Флаг `--bg` сохраняет настройку в Tailscale после перезагрузки —
вторая фоновая служба или собственный рестартер туннеля не нужны.
Если на HTTPS-порту уже опубликовано другое приложение, бот **не
перенаправляет его на Codex** и показывает ошибку в логе.

## 3. Запусти и узнай свой бесплатный URL

```powershell
npm run service -- restart
& "C:\Program Files\Tailscale\tailscale.exe" funnel status
```

Когда Tailscale покажет `https://имя-устройства.имя-tailnet.ts.net`,
открой этот адрес с телефона. Сайтом можно пользоваться через
Telegram Mini App; в обычном браузере сервер не примет команды без
подписанного Telegram `initData`.

В Telegram напиши боту `/app`: он **сам определяет адрес**
действительно настроенного Funnel и присылает кнопку запуска.

Чтобы открывать приложение через постоянную кнопку в профиле бота,
один раз установи этот же URL в BotFather → Menu Button / Mini App.

Для просмотра состояния локальной службы:

```powershell
npm run service -- status
npm run service -- logs
```

## 4. Автозапуск и доступность

- Уже установленный **Windows Scheduled Task** бота запускает весь комплект
  после входа пользователя в Windows. Переустановка службы не требуется.
- Tailscale управляется собственной системной службой и восстанавливает
  Funnel из сохранённой конфигурации. Смена сети и перезагрузка не требуют
  повторного запуска команды `funnel`.
- Если ноутбук **спит, выключен или без интернета**, удалённый Codex недоступен.
  Изменять параметры энергосбережения следует осознанно.
- Если Tailscale не установлен, не вошёл в аккаунт или администратор
  запретил Funnel, локальный Telegram-бот всё равно работает.
- Чтобы отключить публикацию из интернета, выключи
  `TMA_TAILSCALE_AUTO`, перезапусти бота, затем вручную останови Funnel
  командой `tailscale funnel --https=443 off`. Простое выключение
  автозапуска **не удаляет** сохранённую публикацию Tailscale.

## 5. Безопасность и ограничения

- Funnel **публичен**: открыть страницу по URL может любой пользователь
  интернета. Но API Codex закрыт Telegram HMAC-проверкой и allowlist ID.
- Не публикуй через Funnel другие локальные порты, базы данных, консоль
  Codex или диагностические панели без отдельной защиты.
- Tailscale Funnel допускает только HTTPS и адреса в `*.ts.net`.
- Не передавай Bot API token и не размещай `auth.json` в репозитории.
- В TMA пока нет живого WebSocket-потока, drag-and-drop очереди, загрузки
  файлов или встроенного редактора diff. Сеанс с активным Desktop writer
  остаётся только для чтения.

## Ранее установленный Cloudflare Tunnel

Если раньше был настроен `cloudflared`, отключи его **отдельно**
через Cloudflare или старую службу Windows. Новая версия бота больше
не запускает `cloudflared` автоматически. Прежде чем удалять DNS,
убедись, что нет других приложений, использующих этот туннель.

## Старая схема с отдельным VPS

Сохранена для обратной совместимости: `TMA_LOCAL=false`,
`TMA_GATEWAY_URL` и `TMA_AGENT_TOKEN` запускают внешний RPC-агент,
а `npm run tma:gateway` обслуживает шлюз на сервере. Тебе этот режим
не нужен.


## Живая переписка и отчёты (TMA v2)

- Codex app-server отправляет авторизованные SSE-события (ответы, инструменты,
  начало/окончание и ошибки) в Mini App. При разрыве связи поток подключается
  снова с последнего номера события; последние события держатся в памяти.
- Полная сохранённая история Codex продолжает синхронизироваться отдельно
  каждые 5 секунд. Это важно для сеансов Codex Desktop, чьи события могут
  не поступать в app-server нашего бота: их статус отображается как
  **«Наблюдение / статус не подтверждён»**, а не как ложное «готов».
- Состояния `работает`, `ждёт разрешения`, `завершён`, `ошибка` и
  `остановлен` показываются только при получении соответствующих событий.
  Если Codex сообщает о конфликте active writer, отображается «занят Desktop».
  Разрешения по-прежнему выдаются в безопасном Telegram-боте.
- Markdown-текст отображается безопасно, включая блоки кода с подсветкой,
  таблицы и кнопки копирования. Код и HTML из ответов **не исполняются**.
- Скриншоты из последних инструментов отображаются после последнего отчёта.
  Если невозможно точно определить исходное сообщение, карточка явно
  обозначается как материалы из последних инструментов Codex.
- Для новых заданий клиент передаёт `requestId`. Повтор того же запроса
  в рамках работающего процесса бота возвращает прежний результат, не
  запускает ещё одну задачу. После перезапуска самого бота повторную
  отправку следует проверять вручную по истории.
- Для SSE требуется Telegram `initData`; оно передаётся только в заголовке
  защищённого POST-запроса. Поток закрывается до истечения подписи.
  Если TMA открыта слишком долго, закрой её и снова запусти через `/app`.

В локальном режиме Tailscale Funnel никаких дополнительных переменных
или портов не требуется. После обновления репозитория достаточно
`npm ci` и `npm run service -- restart`.


## Фото и живое состояние Codex (обновление TMA)

- Кнопка **«📎 Фото»** возле поля задания позволяет выбрать до трёх снимков
  с телефона, проверить миниатюры и убрать лишние до отправки.
- При необходимости браузер уменьшает изображения до 1600 px и сжимает
  в JPEG до **1,5 МБ на файл**. Поддерживаются JPEG, PNG и WebP;
  несовместимые HEIC-файлы нужно преобразовать или сделать скриншот.
- Изображения передаются как `PromptImage` в **тот же** Codex-сеанс вместе
  с текстом. Все изображения проверяются на размер, base64 и сигнатуру
  файла на ноутбуке. Данные не сохраняются на VPS: TMA работает локально.
- На экране раздельно видны **связь с ноутбуком**, **статус задачи**,
  **давность последней записи журнала** и **время проверки истории**.
  «Подключён» теперь означает только доступность шлюза, а не
  гарантированную готовность Codex. Работа Codex Desktop может
  определяться лишь по активности журнала, без доступа к его writer.
- Лёгкий опрос метаданных сеанса каждые ~4 сек обнаруживает новые записи
  и инициирует обновление истории. Полная история проверяется независимо.
  Замедление каталога сеансов не перекрывает всю переписку предупреждением.
- При потере связи текст и выбранные фотографии сохраняются в форме.
  Повтор запроса с прежним ID остаётся идемпотентным в пределах
  жизни локального процесса бота.

Для установки: `git pull --ff-only origin main`, `npm ci`,
`npm run service -- restart`; затем заново открой TMA через `/app`.


## Дополнительная отказоустойчивость TMA

- Проверка HTTP-шлюза ограничена **6 секундами**. Состояние шлюза и
  подключение самого Codex app-server отображаются раздельно, чтобы
  «ПК подключён» не скрывало проблему Codex.
- Лёгкая проверка доступности выполняется каждые 10 секунд, независимо
  от медленного каталога проектов. После восстановления подключения
  кнопки отправки автоматически становятся доступными.
- Длительная работа Codex с большими журналами больше не должна
  блокировать HTTP-сервер: история читается асинхронно; одновременные
  запросы одной редакции журнала объединяются. При записи во время
  чтения устаревший результат не кешируется как новый.
- Если файл старого Desktop-сеанса отсутствует на диске, поиск по всему
  дереву сессий не повторяется каждые 4 секунды. Отрицательный
  результат кешируется кратко (15 секунд).
- Live-поток отправляет служебный сигнал каждые 15 секунд. При отсутствии
  данных более 48 секунд интерфейс переподключает поток. На мобильном
  устройстве после возвращения Telegram из фона проверяет историю.
- После перезапуска бота новый поток получает новый идентификатор
  поколения: курсор предыдущего процесса сбрасывается, а последние
  события текущего процесса воспроизводятся повторно.
- При медленном интернет-канале сервер закрывает перегруженное SSE-
  соединение вместо неограниченного накопления ответов в памяти.

**Ограничения:** автозапуск Windows происходит при входе в учётную
запись. Если полностью выключен или спит ноутбук, никакая TMA не
сможет выполнять Codex-задачи. История Codex Desktop может обновиться
лишь после сохранения соответствующего сообщения в локальном журнале;
не каждое событие Desktop поступает в app-server бота. Идемпотентность
отправки сохраняется в памяти процесса бота, поэтому после аварийного
перезапуска следует проверять историю перед повторной отправкой.
